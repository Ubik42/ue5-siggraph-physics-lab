## 统一录屏顺序

1. 从中文 Hub 开场，10 秒内说明五个 Case 共享固定步、指标和失败门，但求解器与地图彼此隔离。
2. 每个 Case 保持“正常配置 → 真实交互 → 单变量失败 → 数据证据”的相同叙事顺序。
3. 不追求把五段完整黄金演示塞进一条短视频。主作品视频建议每个 Case 25–40 秒，总长约 3 分钟；仓库内保留各自 45–75 秒完整路径。
4. 结尾回到 Hub，用一张归因表收束：Epic/Chaos/Lyra/ALS/Fab 提供什么，个人实现什么，哪些论文能力没有宣称。

## 面试讲解底线

- “对照”不等于要求研究后端逐帧逼近 Chaos；两者只需消费可审计的同源输入，并分别报告响应。
- “预期失败被成功观测”不等于失败物理配置通过。截图、JSON 与机器门必须同时保留 `expected_failure` 语义。
- GPU 时间必须说明量测区间；CPU 提交、完整 RDG 区间和单 kernel 不能混称。
- Case 02 的 Dragon 派生网格、Case 01 的 Assassin 和 Case 05 的 ALS 动作受第三方许可边界约束，公开仓不重新分发原资产。
- 当前成果是论文启发的 UE 工程复现，不宣称逐篇复刻作者完整代码，也不宣称替换 Chaos。
