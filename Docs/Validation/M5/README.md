# M5 / Case 04 验证证据

## 阻尼弹簧可微反演首切片

- 模块：`PhysicsInverseDesignRuntime` 已进入 `PhysicsInverseDesign` Game Feature；LyraEditor Win64 Development 在 UE 5.4.4 下编译通过。
- 前向合同：归一化质量的一自由度阻尼弹簧，固定步 `1/120 s`、240 步、semi-implicit Euler；位置/速度和三个参数的切线灵敏度按完全相同的离散顺序推进。
- 梯度真值：驱动力、刚度、阻尼三个切线梯度相对中心有限差分的最大误差为 `3.16095e-9`，低于 `2e-5` 门。有限差分只用于验证，不进入优化器。
- 参数反演：由真值 `drive=34, damping=2.8, stiffness=14` 生成位置+速度目标，从 `drive=12, damping=0.4` 出发，18 次受界线搜索把损失从 `1.7055616` 降到 `2.63247e-11`，恢复 `drive=33.999987, damping=2.800026`。
- 收敛证据：19 个损失样本严格单调下降，原始曲线保存在 `inverse_spring_loss_curve.csv`。
- 病态目标：只观察 30 步后的末端位置时，优化同样把损失从 `0.1820384` 降到 `1.6624e-12`，但恢复为 `drive=42.6586, damping=6.1930`，参数 L1 误差 `12.0516`。这证明短时域单观测不可辨识；后续 UE HUD 必须把目标误差和参数可信度分开显示。
- 自动化：`Automation/index.json` 为 `PhysicsResearch.InverseDesign.` 3/3 成功；机器汇总 `inverse_spring_foundation_validation.json`。

该基础门边界：这一组自动化只证明 CPU 可微动力学和优化真值；UE 地图与 Chaos Constraint 证据由下一节独立承担，不能用本节 3/3 自动化替代真实运行验证。

## UE 地图与真实 Chaos Constraint 重放

- 地图：`/PhysicsInverseDesign/Maps/L_InverseSpringChaosReplay`；生成报告 `inverse_spring_map_setup.json`。地图使用专用中文 HUD/GameMode，并放置一个 `AInverseSpringRealtimeActor`。
- 四路同屏：绿色目标轨迹、红色错误初值、青色优化后研究模型、黄色真实 Chaos Constraint。研究轨迹和 Chaos 均使用相同名义质量、刚度、阻尼、平衡位置、初态和 60 Hz 启动协议。
- 研究路径：运行态再次从 `drive=12, damping=0.4` 反演到 `drive=34.00019, damping=2.799986`，损失 `1.69886 → 7.6451e-11`；错误初值处切线/中心差分最大相对误差 `3.2463e-10`。显示尺度与数学尺度分离为 `100 cm / model unit`，没有为画面放大优化参数。
- Chaos 联动：`UPhysicsConstraintComponent` 真实约束 1 kg Chaos 刚体，X 轴位置/速度 Drive 使用恢复的刚度和阻尼，目标位置使用 `scale×drive/stiffness`。120 固定步取得 120 个 Chaos Pose，刚体移动 `228.956 cm`。
- 模型偏差：优化研究轨迹末端目标误差 `0.001135 cm`；Chaos 对研究轨迹 RMS `9.6281 cm`，Chaos 末端目标误差 `0.14554 cm`。作品保留该偏差，证明“同名义参数”不等于离散实现数值完全相同。
- 可复算证据：`Realtime/InverseSpringRealtime.csv/json` 保存 120 个同源步号；验证脚本从 CSV 独立重算 RMS 与两条末端误差，均与运行 JSON 相符到 `1e-6 cm`。
- GUI：`Screenshots/Case04_InverseSpring_ChaosReplay.png` 来自 UE 5.4.4 D3D12 SM6 独立游戏进程。首张图的绿色目标墙遮住部分球体；最终方案缩成轨道外目标柱并提高相机，人工原尺寸检查确认中文 HUD、四个彩色刚体、目标标记和轨道均完整可辨。
- 总门：`inverse_spring_realtime_validation.json` 13/13 检查通过，包含地图、真实 Constraint 源码合同、运动幅度、数值偏差、CSV 复算和截图。

该运行门边界：这一节只证明“可微前向模型 → 参数优化 → UE 可视化 → 真实 Chaos 同参数重放”；交互和病态目标由下一节的独立脚本与失败报告承担。

## 玩家交互与运行态不可辨识失败

- 交互键：`Space` 同时暂停/恢复研究固定步与 Chaos 刚体；`N` 在暂停态先让 Chaos 走下一自然物理帧，再让研究模型推进一个固定步并重新冻结；`R` 重建优化、约束、轨迹和指标；`O` 主动重新优化并重放；`F` 切换不可辨识失败配置；`D` 切换错误初值/目标调试层；`E` 手动导出。
- 自动交互脚本实跑暂停/继续 2 次、自然帧单步 1 次、重新优化 1 次、全链路重置 1 次、调试与导出各 1 次。最终阶段 7 仍重新完成标准 120 步/120 Chaos Pose，标准运行门保持通过。
- 失败配置只改变观测合同：从完整 120 步末端位置+速度，改为只观察第 30 步位置；前向模型、优化器、参数边界、Chaos 约束和 120 步展示时域不变。
- 失败结果：观测损失 `0.64423 → 9.6713e-12`，看似“拟合成功”；恢复参数却为 `drive=23.4743, damping=0.05164`，参数 L1 误差 `13.2741`。继续运行到第 120 步后，研究模型末端目标误差 `115.104 cm`，Chaos 末端目标误差 `116.772 cm`，因此明确记为 `pass=false / expected_failure=true`。
- 失败截图：`Screenshots/Case04_InverseSpring_IdentifiabilityFailure.png` 使用橙色状态栏，同屏显示观测终点 30、极低拟合损失、大参数误差与长时轨迹分离；人工原尺寸检查通过。
- 机器汇总：`inverse_spring_interaction_failure_validation.json` 11/11；失败 CSV/JSON 位于 `Realtime/InverseSpringRealtime_IdentifiabilityFailure.*`。

阶段记录：交互、可解释失败、同参数 Chaos 联动和第一组标准反演基准闭环后，Case04 当时仍缺两个不同动力学/优化性质的程序化基准、作品级成本分布、黄金路径和归因；这些缺口已由后续各节补齐。

## 标准基准 2：二维阻力弹道反演

- 动力学：二维位置/速度在重力与线性阻力下按 `1/120 s` semi-implicit Euler 推进 240 步；参数为水平初速度、垂直初速度和线性阻力。
- 导数合同：三个参数的切线状态与原状态共享完全相同的离散更新；相对中心有限差分最大误差 `2.52893e-11`。
- 联合反演：真值为 `vx=1200, vz=1600 cm/s, drag=0.35`，从 `700/1000/1.2` 出发。首版归一化最速下降被阻力梯度主导，把 `vx` 推到边界并在损失 `491348.6` 停住；阈值未放宽，正式优化改为逐参数解析梯度回溯。
- 正式结果：400 轮、401 个严格单调损失样本把损失从 `1.20904e6` 降到 `0.002757`；恢复 `vx=1200.541, vz=1600.388, drag=0.350497`，以 `1000×drag` 统一量纲后的参数 L1 误差为 `1.4261`。
- 失败边界：只观察最终水平落点时，损失仍从 `229464` 降到 `6.37e-10`，但恢复为 `vx=1777.07, drag=1.23936`，缩放参数误差 `1466.43`。这证明“命中落点”不能唯一辨识初速度与阻力。
- 自动化：`PhysicsResearch.InverseDesign.` 完整回归现为 6/6；机器汇总 `ballistic_foundation_validation.json`，完整收敛曲线 `ballistic_loss_curve.csv`。

阶段记录：完成阻尼弹簧和二维弹道后，第三基准被明确要求进入多自由度耦合系统，不能用另一种单质点轨迹凑数；下节记录该门的最终实现与结果。

## 标准基准 3：六自由度分段弹簧链

- 动力学：固定端串联 6 个单位质量点和 6 根线性弹簧，近端/远端各共享一个刚度参数；末端承受 `0.75 Hz + 1.7 Hz` 双频外力，按 `1/120 s` semi-implicit Euler 推进 240 步。
- 观测合同：标准门使用完整末端位置+速度轨迹，而不是只看最终姿态。两个空间刚度的切线状态与原状态走完全相同的耦合离散更新。
- 梯度真值：近端/远端解析切线相对中心有限差分误差分别为 `6.53e-11 / 8.00e-12`，均低于 `2e-5` 门。
- 参数反演：从 `25/80` 出发恢复真值 `70/30`，14 轮把损失 `8.36289 → 3.32629e-11`；结果 `70.000488/30.000023`，参数 L1 误差 `0.000511`。15 个损失样本严格单调下降，曲线见 `spring_chain_loss_curve.csv`。
- 空间病态边界：只观察最终位置时，损失仍降至 `2.89e-12`，但得到 `6.488/63.382`，参数 L1 误差 `96.894`。它展示的是分段柔度可互相补偿，不与前两个单质点病态案例重复。
- 首次失败保留：首版每步复用了 `SetNumZeroed`，该接口不会清零既有同尺寸数组，力与切线力跨步累积；虽然梯度仍自洽，参数恢复却退化到 L1 误差 `67.87`。正式实现改为每步 `Init(0)`，门槛未放宽；原报告见 `AutomationFirstFailure/index.json`。
- 自动化：完整 `PhysicsResearch.InverseDesign.` 回归为 10/10；机器汇总 `spring_chain_foundation_validation.json`。

## 45–60 秒黄金演示路径

1. `0–10 秒`：进入 `/PhysicsInverseDesign/Maps/L_InverseSpringChaosReplay`，用 HUD 指认绿色目标、红色错误初值、青色研究解和黄色 Chaos 刚体。

3. `22–32 秒`：按 `Space` 暂停、`N` 单步、再按 `Space` 继续，说明共享固定步与 Chaos 自然帧的边界；按 `O` 重做优化。

- Case04 未使用 Assassin 或 Dragon 原资产；公开仓仍只分发个人源码、脚本和证据，不扩大 Epic/Fab 内容许可。
