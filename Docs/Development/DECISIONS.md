# 架构决策记录

## D-001：项目保持 UE 5.4.4

- 状态：已采纳
- 决策：`SIGGRAPHPhysicsLab` 保持 UE 5.4.4（CL 35576357），不跟随其他作品集工程升级到 UE 5.7/5.8。
- 原因：工程、Lyra 基座、ALS 参考和两个 Fab Asset Package 已在 5.4 验证；原地升级会同时扩大算法与资产风险。

## D-002：共享核心 + 五个 Game Feature

- 状态：已采纳
- 共享核心：`Plugins/PhysicsResearch`
- Case 插件：`PhysicsContactCloth`、`PhysicsSoftBody`、`PhysicsFlowMap`、`PhysicsInverseDesign`、`PhysicsDrivenCharacter`。
- 原因：共享固定步进、后端契约、统计和导出；每个作品独立拥有地图、配置、测试与展示资产，既体现 Lyra Game Feature 架构，也防止五个求解器互相污染。

## D-003：Chaos 是基线和引擎集成层

- 状态：已采纳
- 决策：每个 Case 必须明确 Chaos 保留的资产、碰撞、刚体、Cloth/Flesh、缓存、场景查询、异步物理或网络层，以及研究后端替换/扩展的求解层。
- 原因：作品目标是展示对 UE 物理模块和 Chaos 边界的理解，不是把论文效果放进 UE 视口便宣称完成。

## D-004：第三方原资产不可变

- 状态：已采纳
- 决策：`/Game/Assassin` 与 `/Game/FourEvilDragonsHP` 保持只读，派生资产进入个人 Content 或对应 Game Feature；第三方内容不公开再分发。

## D-005：源码管理采用 Git + Git LFS

- 状态：已采纳
- 决策：文本源码使用 Git，`.uasset/.umap` 与常见源素材使用 Git LFS；生成目录和两个 Fab 原资产目录忽略。
- 边界：本轮只建立本地基线，不创建远程、不上传、不发布第三方资产。

## D-006：残差转发必须由可观测安全门保护

- 状态：已采纳
- 决策：残差只在固定拓扑、有限值、残差幅度与完整 CCD 修正均未越界时转发；越界粒子清零并累计回退事件。实时 HUD 和 JSON 必须同时报告当前最大残差与累计回退事件。
- 原因：论文明确指出大残差转发会造成凸起甚至失败。作品不能只展示启用后的最好结果，必须让失效与回退成为运行时可观测状态。

## D-007：真实 Chaos 拓扑先以独立持久会话接入

- 状态：已采纳
- 决策：保留已验证的 300 粒子规则网格论文管线，同时由 `FContactClothGpuExplicitTopologySimulation` 独立承接 Assassin LOD0 的 2011 粒子/5714 边。显式拓扑使用双向 CSR 邻接、真实逆质量分配与跨固定步 Position/Previous/Work Buffer；在动画目标、碰撞和论文 Pass 逐项通过同输入门之前，不以一次性改造破坏现有实时基线。
- 原因：规则网格管线仍有顶行固定、行列邻接和模态基底等结构假设。先证明真实拓扑的生命周期、动力学与异步回读，再逐层合并 NDB、CCD、rank-one 和残差复用，能让每个替换点都有可归因回归证据。
- 边界：双会话是迁移阶段架构，不是最终作品中的两个无关求解器；严格对照仍要求统一角色姿态、空间变换、碰撞输入、固定步和初态。

## D-008：Clothing 蒙皮目标复用 UE 权威路径

- 状态：已采纳
- 决策：每份 Assassin Clothing Asset 继续使用自身 `BoneData → UsedBoneIndices → RefToLocal` 映射，并调用 Epic 的 `ClothingMeshUtils::SkinPhysicsMesh` 生成组件空间目标；研究代码只负责验证资产区间、合并两份输出并上传 GPU，不另写一套近似 LBS。
- 原因：Chaos Cloth 的物理网格骨骼索引是 Clothing Asset 局部索引，直接当 Skeleton Bone Index 会得到错误姿态。复用引擎实现既体现对资产/求解边界的理解，也让 Chaos 与研究后端共享相同蒙皮语义。
- 生命周期门：`GetCurrentRefToLocalMatrices` 只能从姿态缓存已初始化的 `USkeletalMeshComponent` 读取。未注册瞬态组件曾产生 186.448151 cm 误差；注册到瞬态 World 并初始化动画后，参考姿态误差为 0.000022987 cm。运行 Case 必须使用已注册、已更新骨骼的角色组件。

## D-009：动画边界以固定步内最大已观察运动验真

- 状态：已采纳
- 决策：运行 Case 在 BeginPlay 显式加载并播放动画资产，使实验组件 Tick 依赖骨骼组件 Tick；每个共享固定步读取更新后的 RefToLocal，并记录相对初始姿态的最大已观察固定边界运动，而不是只比较循环动画的最后一帧。
- 原因：第一版虽然完成 300/300 次 GPU 目标应用，但依赖序列化动画状态且只保留最终帧位移，报告为 0 cm，无法证明实时姿态真正进入求解器。显式生命周期和跨步最大值将“动画正在播放”“边界确实运动”“目标确实在 GPU 应用”拆成三个独立门。
- 边界：9.2945 cm 是当前 idle 序列在本次 300 步窗口内的最大固定边界运动，不是动画品质黄金常量；自动化只要求非零、有限并保持版本/步号一致。

## D-010：显式拓扑碰撞统一使用组件空间逐步快照

- 状态：已采纳
- 决策：为 Physics Asset 适配器保留已有世界空间入口，同时新增组件空间入口；显式拓扑会话每个固定步从同一已注册 Assassin 组件提取 1 球/16 胶囊，连同 Clothing 蒙皮目标分别捕获不可变版本快照。Jacobi 每轮边约束后对动态粒子执行解析球/胶囊投影，固定粒子只服从动画目标。
- 原因：Clothing 物理网格与 UE `SkinPhysicsMesh` 输出是组件空间，直接混入 `GetBoneTransform()` 的世界空间碰撞体会让非单位 Actor Transform 下的结果错误。显式组件空间接口让边界、碰撞、初态和结构长度共享同一坐标契约。
- 边界：Physics Asset 的 Sphere/Sphyl 分析表示、离散投影和粒子线段完整 CCD 已迁入；仍不包括 Chaos Cloth 的全部碰撞过滤、摩擦、布料自碰撞或论文 NDB/rank-one Pass。

## D-011：Chaos 对照以同组件、固定应用帧和源步号配对

- 状态：已采纳
- 决策：`L_GpuExplicitAssassin` 只保留一个注册的 Assassin `USkeletalMeshComponent`，由它同时提供动画姿态、UE Clothing 蒙皮目标、Physics Asset 解析碰撞和 Chaos Cloth 输出。运行必须使用 `-UseFixedTimeStep -FPS=60`，并在 Case 生命周期内关闭 `p.ChaosCloth.UseTimeStepSmoothing`、退出时恢复原值。Chaos 的 `FClothSimulData` 先按每份资产的 `ComponentRelativeTransform` 转为组件空间，再按拓扑资产区间合并；研究 GPU 异步读回只与完全相同的源步号配对。
- 原因：两个独立角色组件会引入动画时钟偏差；只比较最终帧又无法证明时序同步。固定应用帧和同源步配对建立了可审计的输入合同，但 Chaos 与研究求解器仍使用不同算法、迭代配置和内部状态，因此后端距离是响应差异指标，不是“应趋近于零”的正确性误差。
- 边界：通过门只要求快照覆盖、配对数量、末步、有限指标及各自物理约束有效，不要求数值相等；当前也不把应用固定帧冒充 Chaos 内部每个子系统的完全同构时间积分。

## D-012：显式拓扑完整 CCD 以逆质量判定固定点

- 状态：已采纳
- 决策：显式拓扑使用独立 Compute Pass，从步初位置到 Jacobi 候选位置对当前固定步的球/胶囊快照求最早 TOI，并以 0.01 cm 安全偏移停在入射面。固定点直接读取拓扑逆质量，不复用规则网格的 `ParticleIndex < Columns` 假设。
- 原因：Assassin 的 1307 个固定粒子按两份 Clothing Asset 的 MaxDistance 分布，不能假设它们构成矩形首行。高速 A/B 门必须同时证明离散端点漏检、CCD 截停、非首位固定点不漂移和 Pass 计数。
- 边界：该 Pass 不是布料点/边/三角形自碰撞 CCD，也没有把碰撞体从上一姿态到当前姿态的运动纳入时空 Sweep；当前只对当前帧分析球/胶囊执行粒子轨迹完整扫掠。

## D-013：显式 NDB 使用固定容量的粒子×原语历史

- 状态：已采纳
- 决策：为每个显式拓扑粒子和每个分析碰撞原语保留一个跨固定步 `uint` 连续激活计数，失活及容量内未使用槽归零，固定点按逆质量归零。有限投影使用 `w=k·K^a` 和 `α=w/(1+w)`；Assassin 容量固定为 17，超容量更新被拒绝而不是重建状态或越界。
- 原因：NDB 的可归因收益来自接触历史，不应由距离、硬投影或 CCD 伪造。独立 A/B 只切换 `K=1/K=2`，并同步回读活跃接触对和最大连续激活数。固定容量让渲染线程 Buffer 生命周期稳定，也把 Physics Asset 拓扑变化变成显式失败门。
- 失败记录：`k=0.05` 和 `k=1` 在 Assassin 多原语顺序有限投影中分别留下 0.0416 cm 与约 0.005–0.010 cm 穿透，均未通过原有 `<0.001 cm` 门；正式运行使用 `k=10` 后为 0.000513 cm。CCD 对初始重叠不再写回 TOI=0，避免覆盖 NDB 候选修正。
- 边界：当前状态只覆盖 Physics Asset 分析球/胶囊，不包含布料自碰撞接触对；激活计数上限 30 是稳定性与数值范围保护，不是论文推导出的通用常量。

## D-014：显式模态以结构图低频基替代规则网格索引

- 状态：已采纳
- 决策：Assassin 显式会话从 5714 条结构边构建确定性低频图基，真实逆质量固定点的所有模态值严格置零；缩减系统按 `Uᵀ(mI+kL)U` 组装，并持久上传基、逆矩阵、基础系统和逐粒子外积缓存。完整 `3m×3m` rank-one 分析接触系统每固定步装配一次，GPU Cholesky 求解 36 自由度后限幅回写。
- 原因：Assassin 两份 Clothing Asset 的 1307 个固定点不是规则网格首行，沿用 `ParticleIndex < Columns` 会在数学基、接触装配和回写三层同时破坏固定边界合同。图基让模态与 Chaos LOD0 拓扑、UE Clothing 蒙皮目标及 Physics Asset 接触共享同一粒子编号。
- 失败记录：4 cm rank-one 最大修正让正式 300 步运行穿透达到 0.0011568 cm，超过既有 `<0.001 cm` 门；门槛未放宽，正式限幅改为 2 cm 后穿透为 0.0000858 cm。关闭/开启消融分别执行 0/300 次 rank-one 系统，两组其余模态、NDB、CCD 和输入合同一致。
- 边界：该基是结构图低频工程近似，不声称是论文离线 Hessian 的完整特征模态；rank-one 每固定步装配一次，不等同论文每轮 local-global 内重装配，也不覆盖摩擦或布料自碰撞。

## D-015：GPU 性能以非阻塞完整步 timestamp 与固定稳态窗口报告

- 状态：已采纳
- 决策：显式会话预分配 8 组绝对时间查询，围住每个固定步的完整 RDG 执行区间；渲染线程只轮询已就绪结果，所有槽仍在飞行时记录 skipped 并继续，不调用等待。报告同时保留 300 步原始 CSV、全程分布和固定排除前 16 步后的稳态分布。
- 原因：CPU 提交时间不能代表 GPU 工作，阻塞式 timestamp 又会改变实时调度；固定预热窗口可审计，并避免把启动上传/驱动热身尖峰混入稳定帧预算。验证器从 CSV 独立复算均值、P95、P99 与最大值，而不是只相信运行时摘要。
- 边界：查询覆盖该固定步的上传、全部 Compute Pass 和计划的异步读回复制，因此适合作为作品 Case 的端到端 GPU 步成本；它不是单 kernel 分解，也不替代需要 Pass 级归因时的 Unreal Insights 捕获。

## D-016：重放确定性绑定输入序列，不要求 Chaos 与 GPU 调度逐位一致

- 状态：已采纳
- 决策：`-PhysicsClothExplicitReplay` 从同一 Assassin 动画起点和固定 60 Hz 合同启动；每固定步以 FNV-1a 按位累计步号、2011 个 UE Clothing 蒙皮目标以及组件空间 Physics Asset 球/胶囊。可选 `-PhysicsClothExplicitExpectedInputHash=` 把哈希不一致提升为作品运行失败门。报告和 CSV 使用独立 `gpu_explicit_assassin_replay` 前缀，不覆盖普通演示证据。
- 原因：只说“再次运行”不能证明引擎动画、蒙皮和碰撞输入相同；直接要求 Chaos 或 GPU 时间逐位一致又混入了并行调度与驱动噪声。输入哈希把可控合同与不可控执行差异分开，研究求解器的关键输出另做两次正例一致性检查。
- 失败记录：当前正例哈希为 `429e63168b51a679`；故障注入把末位改为 `0` 后，第三个独立进程得到相同实际哈希但报告 `failed`、`replay_hash_matched=false`。验证脚本随后恢复通过版主报告，负例单独留档。
- 边界：这是由资产、动画和固定步重新生成的输入重放，不是把每帧 2011 顶点快照序列化后逐字节回灌；它证明研究后端输入序列可审计，不承诺 Chaos 内部求解顺序、GPU timestamp 或跨驱动版本结果逐位相同。

## D-017：交互单步必须等待 Skeletal Mesh 的自然 Tick

- 状态：已采纳
- 决策：暂停同时覆盖 `UPhysicsExperimentComponent` 固定步时钟、Assassin 动画和 Chaos Cloth。单步只设置“下一自然帧后再次暂停”的状态：先恢复三者，让 `USkeletalMeshComponent` 按引擎 Tick 依赖推进姿态与 Cloth，完成恰好一个共享固定步后立即再次挂起。禁止从 Actor Tick 手工调用 Cloth 更新或重入组件 Tick。
- 原因：Chaos Cloth 的任务由引擎 TickTaskManager 管理，组件更新不是可重入函数。首版手工调用 `UpdateClothStateAndSimulate` 触发 `InternalData->TaskPointer` 断言；自然帧方案尊重动画、蒙皮、Cloth Task 和实验组件的先后关系，同时保留可审计的单步计数。
- 边界：`B` 改变实际渲染几何与当前观察后端，但两套求解仍在后台同步运行，以持续生成同源曲线和对照证据；它不是销毁另一后端的性能消融开关。

## D-018：玩家失败配置只改变一个求解参数

- 状态：已采纳
- 决策：`weak_ndb` 失败配置只把 NDB 基础权重由标准 `10` 降为 `0.05`；拓扑、动画/Physics Asset 输入、rank-one、CCD、固定步和迭代预算保持不变。运行门要求输入哈希与标准配置一致，且最大穿透必须达到 `0.001 cm` 才算“预期失败已观察”。
- 原因：失败展示应能归因到一个明确物理假设，而不是同时关闭多个安全层或编造穿模。当前 300 步结果由标准 `0.0000858 cm` 变为 `0.0486479 cm`，同时所有 300 次 NDB/rank-one/CCD Pass 仍完成。
- 边界：预期失败报告的 `result=passed` 表示实验基础设施和失败观察合同成立，不表示物理解满足正常质量门；HUD 与 JSON 均单独标记 `expected_failure_observed=true`。

## D-019：Case 02 先建立求解器无关四面体合同，Chaos Flesh 不是硬依赖

- 状态：已采纳
- 决策：`PhysicsSoftBodyRuntime` 先程序化生成低/中/高三档正朝向四面体网格，统一导出静止位置、单元、体积、质量、材料和边界表面。Chaos Flesh/TetMeshing 若后续稳定，则作为同一合同的参考生产者或基线消费者；研究求解器不依赖编辑器 Dataflow 才能运行。
- 原因：UE 5.4.4 隔离启用 `ChaosFlesh` 时，`ChaosFleshNodes` 的 `FExtractGEOInt::Value` 触发 `LogClass Error`，进程收到 Quit 后也未在超时内退出。把实验 Dataflow 设为硬前置会让引擎缺陷污染所有软体算法验证。
- 边界：该 Spike 不证明 `ChaosFleshEngine` 运行时模块不可用。后续仍应评估运行时-only 依赖、程序化 `FTetrahedralCollection` 或可 Cook 的 Flesh Asset；若都不可稳定使用，则以清晰标注的局部 XPBD 自研基线对照多尺度后端，不伪称 Chaos Flesh 已运行。

## D-020：局部 XPBD/Jacobi 是 Case 02 的可击败基线，不冒充论文方法

- 状态：已采纳
- 决策：研究软体首先以结构边距离约束 + 四面体有符号体积约束建立局部 XPBD；每轮从同一旧位置计算约束修正，按顶点聚合后统一回写，并导出完整逐迭代残差。这条路径作为未来 UA-AMG、粗层校正或材料感知全局响应的相同输入/预算对照。
- 原因：MGPBD 和 JGS2 都针对局部迭代难以传播低频误差的问题。若没有明确、可重复且会在困难参数下停滞的局部基线，后续“加速”只能展示效果，无法归因收敛收益。
- 失败记录：初始软边柔度 `2e-5`、24 次迭代在 120 步后最大结构边误差为 572%；第二版为 38.5%，仍未通过 `<25%` 门。未放宽阈值，最终软/硬边柔度 `2e-8 / 2e-9`、64 次预算、速度阻尼 0.98 得到 17.14% 最大边误差、2.10% 平均体积误差与零固定点漂移。
- 边界：当前边约束 + 体积约束不是完整共旋/Neo-Hookean FEM；CPU 墙钟成本也不代表 GPU 性能。双材料压缩响应已有独立位移控制门，材料界面的弯曲、剪切和本构标定仍未覆盖。

## D-021：稳定重力配置与材料对比配置分离

- 状态：已采纳
- 决策：悬臂使用稳定默认柔度与重力/阻尼合同；材料 A/B 使用无重力、零速度历史、8 cm 位移控制边界和显式高对比柔度。运动学目标存于运行态求解器，不写回四面体资产；原始固定点与新增运动学点都以有效逆质量 0 参与约束。

## D-025：扩展性用固定物理域、同预算和非阻塞完整步 timestamp

- 状态：已采纳
- 决策：低/中/高三档共用 `40×20×20 cm`、24 固定步和每步 32 迭代，只改变四面体分辨率。8 槽绝对 GPU timestamp 环包围每个完整固定步 RDG 图，查询只在就绪后消费；报告保留全部样本及 P95/P99/最大值，门槛使用排除 6 步预热后的中位成本严格递增，且高档至少比低档高 20%。

## D-026：GPU 低频投影使用两级并行归约，收敛门与性能门分离

- 状态：已采纳
- 决策：每轮局部约束后，顶点 Gather 先写独立局部修正 Buffer；模态右端由 64 线程组内归约产生部分和，最终 Pass 只遍历部分和并乘静止 `2×2` 逆系统，再逐顶点叠加、限幅、回写。中/高 A/B 只以残差、边/体积误差、固定点和精确 Pass 数判定收敛门；timestamp 目前只门禁完整性，不门禁加速比。
- 原因：单 GPU 线程遍历所有顶点虽能复现 CPU 数学，但不是可扩展 GPU 实现，也会把全局信息传播的收敛价值与串行瓶颈混在一起。两级归约在高档只让最终 Pass 处理 22 个部分和，同时保持模态系数无原子争写。
- 证据：120×32 同预算下，中档残差比为 79.53%，高档为 65.32%；两档最大边误差和平均体积误差均改善，固定端零漂移。每档校正路径执行 3840 次投影、7680 次归约派发、3840 次应用；局部路径投影数为 0。
- 失败记录：单线程投影的正/反 A/B 顺序复跑中，中档局部中位数从 3.48 ms 变到 0.87 ms，校正从 7.21–7.68 ms 变到 3.72 ms；并行归约后仍观察到中位数与 P95 分离。这些数据说明当前长运行顺序混入 GPU 频率/驱动状态，不能挑一组好看数字宣称加速。
- 边界：两个解析模态仍不是 UA-AMG 层级或 JGS2 材料感知远端响应。性能结论必须等反平衡顺序、独立预热或 Unreal Insights Pass 级捕获后再写；当前只宣称同预算收敛收益。

- 决策：`PhysicsFlowMapRuntime` 首先实现独立 2D staggered MAC 网格、确定性粒子、RK2、长/短 Map 和 backward-map Jacobian；Niagara、材质与 Debug Draw 后续只消费快照。直槽显式使用 Clamp 边界，解析旋涡显式使用 Periodic 边界并把 wrap 与粒子丢失分开统计。

## D-034：压力投影先建立 CPU 周期 MAC 真值门，实时预算另做消融

- 状态：已采纳
- 决策：在迁移 GPU 前，用同一 `FFlowMapVelocityGrid2D` 实现周期 Poisson Jacobi 与面速度压力梯度回写；以纯压缩正弦波检查散度和压缩能量是否被移除。PIC P2G 使用归一化双线性面权重，并以均匀速度解析重建单独验证。
- 原因：粒子路径正确并不等于流体不可压缩；若没有独立压力门，后续涡旋视觉可以在散度错误下仍看似合理。CPU 路径是数值真值和未来 RDG 对照，不作为实时性能结论。
- 失败与阈值：512 次 Jacobi 把散度 RMS 从 `1.38617` 降到 `0.00989`，降低 99.286%，未达到既定 99.9% 门。未放宽阈值；1024 次后降到 `7.08785e-5`，比值 `5.11e-5`，最大散度和压缩能量门同时通过。
- 边界：1024 次是 CPU 真值预算，不是游戏帧预算。GPU/多重网格/更优迭代器需要用相同输入报告收敛—成本曲线；当前 PIC 只验证 P2G 数据合同，还不是演化态 PIC/PFM 耗散对照。

## D-035：梯度传输必须在畸变粒子上消融，规则对称采样不能作为贡献证据

- 状态：已采纳
- 决策：先对单个 impulse/标量分量实现 `value + gradient·(grid_position-particle_position)` 的周期 P2G 真值路径；正式对照使用每格一个确定性抖动粒子和相同 `sin(2x)cos(2y)` 场，普通 PIC 与梯度路径共享位置、权重和解析值。
- 原因：规则 2×2 粒子具有强对称性，普通 PIC 的一阶误差已经相互抵消，无法代表 Flow Map 粒子经长时形变后的传输条件。必须让分布畸变保持可重放，才能隔离梯度项贡献。
- 失败与证据：规则分布首测的梯度/PIC RMS 比为 `0.994`，既定“至少降低 25%”门失败；没有降低阈值。确定性畸变分布下 PIC/梯度 RMS 为 `0.036025/0.011289`，比值 `0.3134`，通过同一门。
- 边界：这是向量 impulse 每个分量共用的传输数学验证，不是完整 PFM 时间演化；下一门仍需把向量 impulse、Map Jacobian、压力投影和重初始化连成同预算 PIC/PFM 消融。

## D-036：演化态消融用三路径拆开通信频率与梯度贡献

- 状态：已采纳
- 决策：周期平移基准同时运行 Short PIC、LongMapPic 和 LongMapGradient。三者共享网格、4096 粒子、120×1/60 秒、速度和解析标量；Short PIC 每步重采样 120 次，后两者统一每 20 步重置 6 次，只有第三条启用梯度项。
- 原因：只比较每步 PIC 与完整长 Map 会把“减少有损通信次数”和“梯度重建”混在一起，无法说明论文组合中各部分为何有效。中间的 LongMapPic 是必要消融，不是额外展示后端。
- 证据：三路径 RMS 为 `0.498927/0.123740/0.007644`；梯度长 Map 相对 Short PIC 为 `0.0153`，相对同周期无梯度 Long Map 为 `0.0618`。Short PIC 幅值耗散到 `0.00207`，梯度长 Map 为 `0.97670`，解析幅值 `0.96194`。
- 边界：梯度路径能量代理 `0.2577` 略高于解析 `0.25`，因此结论限定为显著降低耗散与 RMS，不声称严格守恒。当前速度场是给定均匀平移，下一阶段必须验证向量 impulse 回写、压力投影和非均匀旋涡。

## D-037：向量闭环使用 Taylor–Green 稳态旋涡，并要求每步压力投影

- 状态：已采纳
- 决策：粒子由当前非均匀 MAC 速度推进，携带 reference impulse 与 backward-map Jacobian，在线计算 `Bᵀm₀` 后回写 U/V 面；Short PIC 与 Long Map 每步都执行相同 128 次周期压力投影，只改变 Map 重置周期 1/20。
- 原因：给定均匀速度的被动标量只能验证传输，不能证明 impulse 会形成下一步速度。Taylor–Green 是有解析稳态目标的非均匀不可压缩旋涡，可同时量化速度误差、散度、能量和 Jacobian 失真。
- 证据：120×1/240 秒后 Short/Long 速度 RMS 为 `11.1807/1.03065 cm/s`，Long/Short 比 `0.0922`；初始/Short/Long 动能代理为 `99.0393/4.3853/85.9592`。Short/Long 散度 RMS 为 `9.41e-7/3.07e-4`，Long 最大散度 `6.05e-4`，说明 Long Map 保能优势不是通过跳过投影获得。
- 后续更新：D-038 已在同一闭环加入独立 LongMapGradient 路径；本决策中的 Short/Long 原始数据继续作为“只改变重置周期”的历史证据。Jacobian 仍是一阶更新，CPU 真值不能外推为 GPU 实时性能或论文完整实现。

## D-038：向量梯度使用 `BᵀG₀B` 一阶变换，并显式保留能量超调门

- 状态：已采纳
- 决策：在相同 20 步重置周期下增加 LongMapGradient，粒子保存 reference impulse gradient `G₀`；忽略 `B` 的空间导数时用 `BᵀG₀B` 估计当前梯度，并在 U/V 面位置执行一阶 Taylor P2G。Short PIC 与 LongMapPic 保持为两个独立对照。
- 原因：标量分量门已证明梯度重建有效，但只有把梯度接进向量 impulse→压力→速度反馈，才能验证它不会破坏不可压缩闭环。三路径设计也避免把重置周期贡献误归到梯度。
- 证据：Short/LongPic/LongGradient 速度 RMS 为 `11.1807/1.03065/0.017909 cm/s`；梯度/LongPic 比 `0.0174`。梯度路径相对 RMS `0.1266%`、最大散度 `7.14e-4`、Jacobian 行列式最大误差 `1.84e-4`。
- 边界：梯度路径动能 `100.2291` 相对解析 `99.0393` 超调约 1.20%，虽通过 ±2% 门但不是严格能量守恒。`BᵀG₀B` 省略 Hessian 类项，和论文对 noisy Hessian 的取舍一致但不等于完整公式；GPU 迁移必须复现同一误差/散度/能量门。

## D-039：GPU 迁移先以压力子系统建立同预算数值真值，不把阻塞读回包装成实时架构

- 状态：已采纳
- 决策：首个 GPU 里程碑只迁移周期 MAC 压力投影，CPU 与 GPU 共用 32×16 压缩波、5 cm 网格间距和 512 次 Jacobi。Global Shader 由常驻 `PhysicsResearchShaders` 注册；RDG 显式记录 1 次散度、512 次 pressure ping-pong 和 2 次 U/V 回写，验证路径阻塞读回所有面速度做逐值对照。
- 原因：压力投影拥有独立 CPU 真值与明确的 Pass 拓扑，能够先验证 UE Global Shader、RDG Buffer、UAV/SRV、模块加载和 RHI Readback，而不把粒子平流、Map 生命周期和边界栅格化的错误混入首个 GPU 故障面。相同迭代预算避免用更多 GPU 迭代伪造一致性。
- 证据：RTX 4080 / D3D12 SM6 隔离自动化 1/1 通过。初始散度 RMS `1.38617175`，CPU/GPU 投影后为 `0.00988997345/0.00989034952`；GPU/CPU 所有面速度最大误差 `3.60012e-5 cm/s`，散度差 `3.76e-7`，7/7 NullRHI 回归保持通过。
- 边界：该门证明数值与 UE GPU 调度合同，不证明实时性能。阻塞 Readback、无 timestamp、无持久跨帧资源；下一阶段必须建立异步会话并迁移粒子、Map/Jacobian 与 impulse/梯度闭环，再接入 Chaos 运动障碍。

## D-040：持久压力会话以外部 RDG 资源跨步，U/V 快照必须成对并携带源步号

- 状态：已采纳
- 决策：FaceU、FaceV、散度和两份压力工作 Buffer 在初始化时转为 `FRDGPooledBuffer`，每步重新注册为 RDG 外部资源；当前/工作面速度只交换引用，不重新上传初态。游戏线程 `EnqueueProjectionStep` 只排队；U/V 两个 Readback 同时创建、同时就绪后才发布一个快照，并记录产生它的固定步号。
- 原因：只持久化压力、每步重传速度仍不具备实时状态语义；U/V 分开发布则可能把不同 GPU 步拼成一个伪速度场。源步号是后续与粒子快照、Chaos 障碍变换和表现层对齐的必要合同。

- 边界：自动化结束才调用 `FlushAndWaitForReadbackForValidation`，不能据此声称运行期完全无同步成本；正常 Initialize/Enqueue/Request/Poll 路径没有 Flush 或 GPU Idle。当前会话无 timestamp，粒子、Map/Jacobian、边界与 impulse 仍待迁入。

## D-041：GPU 粒子以位置与 Backward Jacobian 双状态跨步，周期回卷只在真实越界时发生

- 状态：已采纳
- 决策：粒子状态拆为两份 `float4` 持久 Buffer，联合保存位置和 `2×2` backward-map Jacobian；每步在周期 staggered MAC 场上做 RK2，中点速度梯度形成 `I-dt∇u` 并右乘旧 Jacobian。两份状态必须成对 ping-pong、成对读回并携带源步号。周期取模仅在坐标实际离开 `[min,max)` 时执行。
- 原因：位置正确但 Jacobian 留在 CPU 不能支撑后续 `Bᵀm₀`；拆开发布两份 Buffer 会产生不一致 Map 状态。对所有域内粒子无条件 `fmod` 既无物理意义，又会放大 CPU/HLSL 浮点取模差异。
- 首轮失败与证据：无条件回卷时，20 步最大位置误差 `5.11568e-4 cm`，未通过 `1e-4 cm` 门；未放宽阈值。只在越界时回卷后，1024 粒子位置误差降到 `3.81470e-6 cm`，Jacobian 分量/行列式差为 `8.34465e-7`，20 个排队步、20 个平流 Pass、最终第 20 步快照均精确。
- 边界：当前粒子消费静态速度场，不携带 reference impulse/gradient，也没有 P2G、压力反馈、Map 重置或 timestamp。下一门必须把粒子与压力两个独立会话合并，不能用并排运行冒充完整 GPU Flow Map 闭环。

## D-042：Impulse/梯度 P2G 首版使用确定性面 Gather，不用浮点 Atomic 作为真值

- 状态：已采纳
- 决策：每个 U/V 逻辑面线程按固定粒子顺序 Gather 双线性贡献并归一化；粒子先计算 `m=Bᵀm₀`，梯度模式再以 `G=BᵀG₀B` 在逻辑面位置做一阶 Taylor 重建。普通与梯度模式共享畸变位置、非单位 `B`、reference impulse 与 `G₀`，只切换梯度项。
- 原因：Scatter P2G 的浮点 Atomic 加法顺序随 GPU 调度变化，不适合作为 CPU/GPU 数学首门，也会让重放哈希和逐面误差难以归因。面 Gather 虽为 `O(face×particle)`，但在作品当前网格规模可接受，并为后续 tiled/binning 优化提供确定真值。
- 证据：16×16、256 粒子下，普通 `Bᵀm₀` 最大面误差 `2.86102e-6 cm/s`，`BᵀG₀B` 梯度路径为 `5.72205e-6 cm/s`；两模式分别精确执行 U/V 两个 Pass，RTX 4080 / D3D12 SM6 自动化 1/1 通过。
- 边界：阻塞式接口只用于数学门；当前 Gather 尚未消费持久粒子 Buffer，也未直接写入持久压力会话。不能把三个独立通过的子系统描述成完整 GPU Flow Map，下一门必须在同一 RDG 固定步内按“平流→P2G→压力→新速度”串联。

## D-043：统一 GPU 固定步必须让投影速度真实反馈到下一步粒子，并统一标记四 Buffer 快照

- 状态：已采纳
- 决策：持久闭环每次 Enqueue 固定执行“当前投影速度 → 粒子 RK2/Backward Jacobian → impulse/梯度面 Gather → 散度/压力 → 新投影速度”。粒子 ping-pong 引用在 Execute 后交换；压力输出写回持久 Current U/V，下一次 Advect 必须读取该 Buffer。速度 U/V 与粒子 A/B 四个 Readback 全部就绪后才发布一个源步快照。
- 原因：若每步粒子仍读取初始化速度，或速度与粒子分别发布，就只是把已通过的子系统装进一个类，仍不构成 Flow Map 反馈闭环。统一源步号也是后续 Chaos 障碍变换、Niagara 表现和指标对齐的基础。
- 证据：16×16、256 粒子、4×1/240 秒、每步 64 次压力预算下，平流/Gather/散度/Jacobi/Apply 精确为 `4/8/4/256/8`；最终四 Buffer 快照为第 4 步。CPU/GPU 散度 RMS `1.65896e-6/1.66251e-6`，最大面速度误差 `1.83582e-5 cm/s`，Jacobian 行列式最大偏差 `1.60635e-4`。
- 边界：4 步尚未触发 Long Map 重置；reference impulse/gradient Buffer 当前只读。无 timestamp、固体边界和 UE 运行 Actor。下一门必须跨越重置周期并证明 payload 与 `B=I` 在 GPU 原位更新。

## D-044：GPU Map Reset 必须在压力 Apply 后重采样 payload，并显式改变 ping-pong 归属

- 状态：已采纳
- 决策：重置步仍先完成正常平流、`Bᵀm₀/BᵀG₀B` Gather 与压力投影，再以最终 Current U/V 在粒子位置重采样 reference impulse 和梯度，并把 backward-map Jacobian 设为单位阵。普通步写 ParticleWork 后交换；重置步把重置结果写回 ParticleCurrent，执行后不交换，异步快照也读取 Current。
- 原因：若在压力前重采样，下一周期的 reference payload 不代表真正反馈速度；若重置后仍交换，下一步会重新读取重置前的 Work 状态；若快照仍读 Work，报告会把临时 Jacobian 冒充重置结果。三者都属于资源生命周期错误，单看画面很难发现。
- 证据：16×16、256 粒子、8×1/240 秒、4 步重置周期下，CPU/GPU 各重置 2 次，平流/Gather/散度/Jacobi/Apply/Reset Pass 精确为 `8/16/8/512/16/2`。第 8 步四 Buffer 快照的 Jacobian 单位阵与行列式误差均为 0；CPU/GPU 面速度最大误差 `2.00272e-5 cm/s`，散度 RMS `1.60987e-6/1.60001e-6`。
- 边界：该门没有 GPU timestamp、运动固体边界、UE Actor、Niagara 表现或玩家交互。重置周期固定为步数合同，尚未加入基于 Map 失真的自适应重置；下一阶段先补非阻塞 GPU 时间，再让 Chaos 刚体变换进入同一步边界数据。

## D-045：GPU 时间使用 8 槽非阻塞绝对时间查询，满槽必须记 skipped 而非等待

- 状态：已采纳
- 决策：每个 Flow Map 固定步在创建 RDG 图前写入 Start Query，在 `GraphBuilder.Execute` 后写入 End Query；8 组 `RQT_AbsoluteTime` 成对循环使用。查询结果只用 `wait=false` 轮询，槽满时该步不计时并增加 skipped，不在运行 Enqueue 内 Flush 或 GPU Idle。统计同时保存原始步号/毫秒、全样本与剔除固定预热步后的均值、P95、P99 和最大值。
- 原因：渲染线程构图时间不是 GPU 执行时间；逐步阻塞查询又会改变被测流水线。显式记录 skipped 比静默丢样更可审计，原始步号则允许后续识别重置步和读回步的成本。
- 证据：RTX 4080 / D3D12 SM6 隔离门连续排入并执行 32 步，8 个样本完成、24 步因槽满显式跳过，总数精确为 32。预热 4 步后保留 4 个样本；全样本均值/P95/P99/最大值 `4.346/6.347/6.347/6.347 ms`，稳态 `4.336/6.347/6.347/6.347 ms`。13/13 Flow Map NullRHI 回归保持通过。
- 边界：快速批量自动化只验证机制，4 个稳态样本不能作为作品级性能结论。正式地图需按真实帧运行更长序列、导出原始 CSV 并独立复算。该区间覆盖完整固定步 RDG 和当步计划的读回复制，不等于单一 Shader kernel 时间。

## D-046：Chaos 只提供权威刚体 Pose，Flow Map 负责将其转换为 staggered 固体边界

- 状态：已采纳
- 决策：Case03 接收 UE/Chaos 刚体前后 `FTransform`、碰撞半径和固定步；由位置与 UE Z/Yaw 差分得到平面线速度、角速度。Flow Map 自己分别在 Cell 中心、U 面和 V 面栅格化固体占用，并在被覆盖面保存 `v_body+ω×r` 无滑移速度。零固定步、非有限 Transform 或非正半径必须在任何栅格化前拒绝。

## D-058：用 UE 5.4 token 解析做组件归因，不把合包流量强拆给单个组件

- 状态：已采纳
- 决策：按引擎 `NetworkProfiler.cpp` 的 v14 格式实现只读导出器，严格校验 Magic、版本、token 边界和 EndOfStream。RPC 使用 Profiler 的 header/parameter/footer 总 bits；属性使用实际 ReplicateProperty payload，并分别计入可观测的 content block、property handle/header token。P95/P99 对四次服务器更新的归因 token bits 使用 Nearest-Rank。
- 结果：客户端 `ServerRequestRecovery` 恰好一次，`18+11+0=29 bits`。服务端恢复窗口有 4 次 FallState、3 次 RecoveryBranch；Recovering 组合发 3 次，其中 2 次为约 328ms 间隔的纠错重发，随后 Recovered 发 1 次。属性 payload 21 bits；四次归因样本 `51/35/35/64 bits`，合计 185 bits，P95/P99 均 64 bits；机器门 11/11。
- 格式边界：client `[2]` 会话开头的 queued SendBunch 仍引用上一会话 channel-name index。解析器只允许 SendBunch channel type 出现显式 unresolved，占 1 次；其他 name index 仍必须严格有效，两端都必须完整走到 EndOfStream。
- 声明边界：Network Profiler 没有单列 packed content-length，也不能把同一 datagram 内的 Lyra 其他 Actor、包头、ACK、合包和重传字节无歧义分配给单个组件。因此 185 bits 称“Profiler 可归因 token”，不称独立 UDP/IP 线速字节；整场 SocketSendTo 仅作上层会话证据。

## D-060：第三标准基准必须用等反向耦合和消融证明扰动传播
