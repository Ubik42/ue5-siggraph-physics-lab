# Case 02：GPU 多尺度软体复现范围

## 论文锚点

- *MGPBD: A Multigrid Accelerated Global XPBD Solver*（SIGGRAPH 2025，DOI 10.1145/3721238.3730720）：以对偶空间 UA-AMG + PCG 解决局部 XPBD 的低频停滞，固定拓扑下缓存层级并延迟更新。
- *JGS2: Near Second-order Converging Jacobi/Gauss-Seidel for GPU Elastodynamics*（SIGGRAPH 2025，DOI 10.1145/3731183）：为顶点局部 3×3 更新预计算材料感知的远端响应，并用共旋与 cubature 保持在线成本。

本作品定位为“受 MGPBD/JGS2 启发的工程复现”，不会在尚未实现论文完整 UA-AMG、自举近零空间、逐顶点全局响应和 cubature 训练前宣称完整论文复现。

## 当前第一阶段合同

1. 程序化规则块使用一致的体对角线六四面体分解；所有单元被纠正为正朝向。
2. 低/中/高三档分别为 `4×2×2`、`8×4×4`、`16×8×8` 单元，预期为 96/768/6144 个四面体。
3. 每个网格导出静止位置、四面体索引、正静止体积、质量/逆质量、双材料编号和唯一边界三角形；最小 X 面固定。
4. CPU 真值必须验证总体积等于解析长方体体积、固定点数量正确、边界面无非流形复用、双材料都存在，并拒绝零维输入。
5. Dragon 原始 FBX 当前有边界边和多个连通分量，只作为最终美术来源；未完成个人派生封闭修复前不得直接送入四面体生成器。

## Chaos Flesh 隔离 Spike

UE 5.4.4 以 `-EnablePlugins=ChaosFlesh -NullRHI -Unattended` 隔离启动时，插件能够挂载并完成编辑器初始化，但引擎报告：

`LogClass: Error: IntProperty FExtractGEOInt::Value is not initialized properly ... Module:ChaosFleshNodes File:Public/Dataflow/ChaosFleshImportGEO.h`

命令收到 `Quit` 后仍未在合理超时内退出，因此主工程继续默认不启用 Chaos Flesh。该结果只证明当前安装版本的 Dataflow 节点层有启动缺陷，不证明 `ChaosFleshEngine` 的运行时求解代码不可用；后续可尝试只依赖运行时模块或使用程序化 `FTetrahedralCollection`，但不能让实验插件阻塞 Case 02。

## 分阶段门槛

1. 四面体数据合同与 CPU 体积真值。
2. 局部 XPBD/Jacobi 软体基线：悬臂梁、位移控制压缩块与软/硬/分区材料响应均已完成。
3. 已完成第一项全局响应加速子集：两模态低频校正与相同迭代预算局部基线进行残差、结构和体积误差消融。
4. D3D12 持久 GPU 会话、低/中/高分辨率扩展性与非阻塞读回。
5. Chaos/Flesh 可用层或清晰替代基线、Dragon 派生外壳绑定、玩家交互、失败场景、GUI 与归因。

## 局部 XPBD/Jacobi 悬臂基线

`FSoftBodyLocalXpbdSolver` 直接消费第一阶段四面体合同。每个 1/60 秒固定步先执行阻尼 Verlet/重力预测，再以结构边距离约束和每个四面体的有符号体积约束组成局部 XPBD 系统；软/硬材料分别使用不同柔度。每轮约束在旧位置上并行计算修正，按顶点聚合、限幅并松弛回写，因此它是后续多层/全局响应要比较的局部 Jacobi 基线，不是 MGPBD 或 JGS2 本身。

低档 `4×2×2` 悬臂含 45 顶点、96 四面体、180 条唯一结构边，最小 X 面 9 个点固定。120 步、每步 64 次局部迭代结果为：

- 归一化残差 RMS `0.0350246`；最大结构边相对误差 `0.171402`。
- 平均/最大体积相对误差 `0.0209630 / 0.0682082`，总体积比 `1.009258`。
- 自由端向下位移 `10.7045 cm`，固定面漂移为 0。
- 首固定步从 1 次到 64 次迭代，残差 `0.00215940 → 0.00144248`；64 个逐迭代样本严格单调下降并导出 CSV。
- 当前机器 CPU 平均/最大固定步成本约 `0.293 / 0.338 ms`。这里只作为低档 CPU 参考，不外推为 GPU 或高分辨率性能。

初始工程参数 `SoftEdgeCompliance=2e-5`、24 次迭代、阻尼 0.995 在 120 步后产生 572% 最大边误差；第二版虽将总体积收口，固定端最坏边仍为 38.5%。测试门没有放宽，最终使用软/硬边柔度 `2e-8 / 2e-9`、64 次预算与 0.98 阻尼，才通过既定 `<25%` 最大边误差门。这些参数是 UE 厘米/千克工程基线，不宣称对应论文材料标定。

## 位移控制压缩与双材料 A/B

求解器提供逐顶点运动学目标，不修改原始四面体网格。压缩基准将最大 X 面 9 个顶点精确向内移动 8 cm，最小 X 面仍固定；重力关闭、速度历史清零，三组只切换材料编号：均匀软、均匀硬、X 中点分区。为了让材料柔度在 UE 厘米/千克尺度的 `α=compliance/Δt²` 中产生可观测差异，该基准显式使用软/硬边柔度 `2e-3 / 2e-5`、软/硬体积柔度 `20 / 0.2`，不覆盖稳定悬臂的默认配置。

64 次相同预算结果：均匀软块平均体积误差 `0.198760`、总体积比 `0.802146`、残差 `0.277425`；均匀硬块为 `0.151133 / 0.854474 / 0.170961`；分区块总体积比 `0.833758`，位于两组均匀响应之间。三组最大运动学目标误差均为 0。

第一版材料 A/B 误差几乎完全相同（软/硬平均体积误差都约 0.06774），暴露了原柔度相对距离/体积梯度分母过小、材料差异被数值淹没的问题。直接把极端对比配置改成全局默认又使重力悬臂下垂 961 cm；最终把“稳定重力基线”和“位移控制材料对比”拆成两个明确实验配置，而不是用一套参数同时证明两件事。

## 两模态全局低频校正工程子集

局部约束聚合后，求解器可选地把逐顶点修正最小二乘投影到沿静止包围盒主轴的两个全局基函数 `t` 与 `t²`。两者在固定端 `t=0` 严格消失，运动学/固定点不参与拟合；投影结果以独立强度叠加到局部修正，并继续接受同一顶点限幅与 Jacobi 松弛。该路径默认关闭，因此既有 64 次局部悬臂和材料压缩基线不变。

低档悬臂在完全相同的 120 步、每步 32 次迭代预算下，局部/校正最终残差为 `0.0641992 / 0.0460289`，校正路径为局部的 `71.70%`；最大结构边误差由 `0.339341` 降至 `0.234055`，平均体积误差由 `0.0340260` 降至 `0.0275973`，固定端漂移均为 0。第一次 16 次预算虽然残差比值已为 `83.37%`，但校正路径最大边误差仍为 `45.08%`，因此没有放宽质量门，而是把正式同预算消融设为 32 次。

这一步证明“跨全体顶点传播的低频响应”能击败纯局部基线，但没有构造粗四面体层级、UA-AMG/PCG、材料感知远端 3×3 响应或 cubature，因此明确标为 MGPBD/JGS2 启发的工程子集，不称论文完整复现。

## GPU 约束布局与迭代调度合同

GPU 输入由 CPU 从同一四面体合同确定性派生：唯一结构边按顶点编号排序；每个顶点分别持有 incident edge 与 incident tetrahedron 的 CSR Offset、约束索引和局部 Corner。低/中/高三档产生 180/1152/8160 条唯一边与 96/768/6144 个四面体，CSR 关联数精确为 `2E` 与 `4T`。验证同时破坏 CSR 末端 Offset，确认越界布局会在上传前被拒绝。

持久 D3D12 迭代不会让边/四面体线程直接原子争写顶点位置，而是拆成距离约束、体积约束、顶点 Gather/Apply 三段；每约束 Lambda 在固定步开始清零、迭代间持久，位置/前一位置/工作区跨固定步持久。Case01 的早期 Shader 注册、外部 RDG Buffer 和异步 Readback 生命周期被复用，软体约束数学与 CSR 则保持 Case02 独立所有权。

真实 RTX 4080 / D3D12 SM6 门已运行低档悬臂 120 步、每步 32 次，三类 Pass 各 3840 次。最终 GPU 残差 `0.0606721`，同预算 CPU 为 `0.0641992`，比值 `0.945061`；GPU 最大边误差 `0.320076`、平均体积误差 `0.0330536`、自由端下垂 `18.5538 cm`、固定端漂移 0。会话完成 2 次异步快照，最终快照精确对应第 120 步；正常运行接口不等待 GPU，只有自动化最终取证辅助函数显式 Idle/Flush。

首版真实 GPU 输出退化到残差 `0.880155`、体积误差 1、固定端漂移 `23.1002 cm`。逐步缩到 Integrate-only、单边 Gather、四面体 Gather 后确认上传与 CSR 正确，最终定位为同一 HLSL 全局资源名在约束 Pass 中声明 `RWStructuredBuffer`、在 Gather C++ 参数中却按 SRV 绑定，导致 Shader 反射类型错位。现在约束输出 UAV 与 Gather 输入 SRV 使用不同参数名但引用同一 RDG Buffer；门槛未放宽。

## 固定物理域的 GPU 扩展性证据

扩展性门保持梁的物理尺寸为 `40×20×20 cm`，低/中/高仅改变离散分辨率：45/225/1377 顶点、180/1152/8160 边、96/768/6144 四面体。三档均执行 24 个固定步、每步 32 次同一距离/体积/Gather 迭代，避免把更大场景或不同预算混入分辨率比较。

每个固定步的完整 RDG 图由 8 槽 `RQT_AbsoluteTime` 环包围；查询只在就绪后消费，槽满则记 skipped 而不等待 GPU。自动化逐步只保证游戏线程到渲染线程的提交已经发生，不调用逐步 `BlockUntilGPUIdle`；最终取证才允许等待。排除前 6 步预热后，低/中/高各有 18 个稳态样本，完整 24 个样本均保留在 CSV，三档 skipped 都为 0。

RTX 4080 / D3D12 SM6 的稳态中位完整步成本为 `2.954 / 3.486 / 3.864 ms`，P95 为 `3.031 / 3.548 / 3.936 ms`；高档中位数比低档高 30.8%。该结果证明成本随离散规模单调上升，也显示低、中档仍受固定派发与 GPU 并行平台影响，因此不拟合线性复杂度、不把 P95 尖峰包装成吞吐规律。

更重要的是，相同 32 次局部迭代预算下，低/中/高残差为 `0.08855 / 0.25986 / 0.47761`，最大结构边误差为 `0.47734 / 1.59070 / 3.10265`。这不是高档物理质量通过，而是清楚暴露“网格越细，局部信息在固定轮数内越难传播”的停滞；GPU 两模态校正或真正多层求解必须在相同输入和预算下显著降低中/高档残差，才能进入作品结论。

首个扩展性测试把三档批量排队，8 槽查询环只取得 8–15 个样本，而且驱动共享尖峰让中档 P95 反而略高于高档；该设计被废弃。第二版虽然取得完整样本，但要求每相邻档 P95 按固定倍数增长，错误地忽略了 GPU 并行平台。正式门改为审计完整样本、稳态中位成本严格递增且高档至少比低档高 20%，同时仍保留 P95/P99/最大值供诊断；这是一条调度/成本门，不替代物理质量门。

## GPU 两模态低频消融

GPU 校正与 CPU 工程子集使用同一主轴解析基 `t / t²`，固定端的基在 `t=0` 自然消失。每轮距离/体积约束后，GPU 先产生逐顶点局部修正，然后为两个基投影右端、求 `2×2` 系数并叠加回顶点。系统矩阵逆在 CPU 上由静止基与自由点预计算，运行时只归约右端。

首版投影由一个 GPU 线程遍历全部顶点：物理收敛收益稳定，但中/高档计时出现与运行顺序相关的反常分布。正式实现改为 64 线程组内并行归约，每组写两个 `float3` 部分和，最终 Pass 只遍历 4/22 个部分和。这条 RDG 链每轮是 Gather Correction → Partial Reduction → Finalize → Apply，不让多线程原子争写模态系数。

中/高档在完全相同的 120 步、每步 32 轮预算下只切换低频校正：中档残差 `0.198919 → 0.158200`（降低 20.5%），高档 `0.549605 → 0.359026`（降低 34.7%）；最大边误差与平均体积误差在两档都同向降低，固定端零漂移。校正路径每档精确执行 3840 次语义投影、7680 次两级归约派发和 3840 次应用，局部对照的投影数为 0。

原四条路径各有 120 个完整非阻塞 timestamp、0 跳过，但反转 A/B 顺序后中位数和 P95 明显变化，因此只作为查询完整性与尾部风险证据。正式性能归因另建 ABBA 会话：中/高档分别以 Local → Corrected → Corrected → Local 运行四个全新会话，每个 128 步、排除前 48 步、保留 80 个稳态样本，合计每档 512 个 timestamp 且跳过 0。

ABBA 中档的局部/校正会话中位均值为 `4.0315 / 4.6265 ms`，高档为 `4.430 / 5.196 ms`，即两模态路径在当前 RTX 4080 上增加 `14.76% / 17.29%` 完整步中位成本。结构归因不是黑盒差值：每个 128×32 校正会话精确新增 4096 次语义投影、8192 次两级归约派发和 4096 次应用。联合独立收敛门的中/高残差至少降低 15%/25%，当前作品结论是“有限额外 GPU 成本换取显著高分辨率收敛质量”，不是加速比。局部 ABBA 两端仍有约 28–32% 中位漂移，因此这些数字只作为机器/协议证据，不外推为通用 GPU 定律。

## TerrorBringer 派生封闭外壳与 Cage 绑定

原 TerrorBringer FBX 有 1048 条边界/非流形边和 28 个连通分量，不进入体网格生产者。本地派生链使用 Blender 5.2 对一份只读 FBX 导出件做体素封口，体素尺度为最大边界尺寸的 `1/64`，然后减面到 6000 三角形。正式拒绝门要求边界边 0、非流形边 0、连通分量 1 且符号体积非零；这四项全部通过后才导入 `/PhysicsSoftBody/DragonDerived/SM_TerrorBringer_SoftBodyCage`。

UE LOD0 导入后为 4854 个可 CPU 访问的表面顶点。当前作品化数据路径用一个覆盖外壳 Bounds 的 `8×8×8` 规则体积 Cage（729 顶点、3072 四面体）；每个表面顶点保存所在六面体的 8 个节点和三线性权重。静止表面重建最大误差为 `0.000141 cm`，对 Cage 施加一个固定端消失的 40 cm 弯曲场后，表面最大位移为 `39.9993 cm`；最小 X 面 81 个 Cage 顶点保持固定。

这条绑定是明确的工程替代：它让四面体求解与有机 Boss 表面在 UE 中产生可验证联动，但没有构造贴体四面体，体积 Cage 包含空气区，权重也不是单四面体重心坐标。当前已完成真实运行闭环：持久 GPU 四面体会话执行 300 固定步，按异步 Cage 快照通过权重刷新 `UDynamicMeshComponent` 的 4854 个表面顶点；标准地面接触下最大形变 `37.354 cm`、最大穿透 0、最终接触点 53、固定端漂移 0。玩家可暂停、单步、真重置、切换 Cage 调试、导出指标，并以 `F` 做标准/弱接触单参数消融。

## Chaos/Flesh 结论与 CPU 替代对照

二次审计确认，UE 5.4.4 的 `ChaosFleshEngine` 属于 `ChaosFlesh.uplugin`，通过正常项目依赖启用时无法绕开同插件的 `ChaosFleshNodes` 装载路径；此前 `FExtractGEOInt::Value` 的反射属性错误因此仍会污染启动。当前没有修改引擎插件描述、屏蔽错误或伪造 runtime-only Flesh，而是把程序化四面体合同交给已有 CPU 局部 XPBD 真后端，明确标注 `not_chaos_flesh=true`。

CPU/GPU 实景对照共用 4854 点 Dragon、729 点/3072 四面体 Cage、1/60 秒、300 步、每步 32 次、重力、阻尼、两模态校正、地面与接触刚度。CPU 后端完成 300 次同步表面刷新、9600 次低频投影、300 次接触投影，平均固定步约 `5.968 ms`，固定端与地面穿透为 0；但最大表面形变达到 `978.277 cm`，相对 GPU 标准路径的 `37.354 cm` 构成明确物理质量失败。报告用 `passed_expected_failure` 表示“真后端执行合同完成且预期局部传播失败已观测”，同时固定 `physics_quality_gate_passed=false`。

`B` 后端键会释放当前 GPU 会话、恢复静止 Cage/表面、初始化 CPU 求解器并把共享实验步号归零，不只是改 HUD 标签。自动脚本先让 GPU 执行 30 步，再触发一次相同切换路径，CPU 随后重新完成 300 步。该对照证明作品具备 UE 固定步生命周期、后端状态切换、动态表面和可解释失败门，但不声称 CPU 路径等价于 Chaos/Flesh，也不拿 CPU 墙钟与 GPU timestamp 直接计算加速比。

派生 UAsset 依然受 Fab 源包许可边界约束，只保留在本地并被 Git 精确忽略。源码仓只提交生成/导入脚本、绑定代码和不含几何的统计报告；恢复时必须先通过 Epic 账户把原 Dragon 包加入工程。

## 当前探索结论

Case 02 已通过 `Scripts/Validation/validate_m3_case02_acceptance.ps1` 作品级总验收。它不是一段孤立 Shader，而是一条 UE 物理模块完整链路：求解器无关四面体合同、CPU 局部基线、持久 D3D12 XPBD、并行低频校正、异步读回、Dragon 表面绑定、动态网格渲染、固定步生命周期、玩家状态控制、地面接触消融、后端重建和机器可读指标共同闭环。

作品能够证明对 Chaos 生态边界的理解，但不把“调用 Chaos”当作唯一标准：UE 负责资源、Game Feature、对象生命周期、输入、地图、渲染与实验外壳；研究求解器负责可审计的约束、接触和 GPU Pass；Chaos/Flesh 的本机版本缺陷被隔离记录，CPU 替代后端也明确标注为非 Flesh。总验收要求 11/11 NullRHI 回归、14 份组件报告、真实 D3D12 SM6、6 张运行截图和全部授权边界同时成立，因此 Case 02 可以冻结为独立复现作品，后续改动若破坏任一合同会直接失败。
